# img2bin_qoi 使用说明

原始 QOI 压缩取模工具：QOI 系中压缩手段最全的一个——64 项哈希字典、小差分、大差分、行程、原始块五类 op 全部启用，压缩率通常最好。解码端需要维护一张 64 项字典（每项 4 个通道值）和前像素状态，不支持从流中间跳转解码。

## 快速开始

- **双击运行**：第一次双击自动创建 `input`、`output` 文件夹；把图片放进 `input` 再双击一次（默认 `rgb565`、大端）
- **拖拽**：把图片或文件夹拖到 `img2bin_qoi.exe` 上
- **命令行**：

```powershell
.\img2bin_qoi.exe --input .\demo.png --output .\out --format argb8888
```

## 参数

| 参数 | 说明 |
| --- | --- |
| `--input <file-or-dir>` | 输入文件或目录（默认 `<exe_dir>\input`） |
| `--output <dir>` | 输出目录（默认 `<exe_dir>\output`） |
| `--format <name>` | 单一像素格式（默认 `rgb565`） |
| `--formats <all\|f1,f2,...>` | 一次输出多种格式（`all` 自动跳过 `a8/a4/a2/a1`） |
| `--little-endian` | 小端输出（默认大端） |
| `--bg-color <RRGGBB>` | 非 Alpha 格式的透明区域先与该背景色混合（默认 `000000`） |
| `--manifest` | 在输出目录写 `img2bin_qoi-manifest.json` 运行清单（默认关闭） |
| `--info` / `--list-formats` / `--help` | 元数据 JSON / 格式清单 / 帮助 |

每写出一个文件，stdout 报告一行体积率（压缩后 payload / 同格式无压缩 payload，通用头 6 字节两边不计入）：

```text
Wrote out\photo_rgb565_qoi_be_128x64.bin (3200 bytes, payload 3194 / raw 16384 = 19.5%)
```

退出码：`0` 成功；`1` 参数错误；`2` 输入错误；`3` 编码错误；`4` 写入错误；`5` 内部错误；`6` 批处理部分失败。错误详情以单行 JSON 写到 stderr（字段：`code`、`exit_code`、`message.zh_cn/en`、`file`、`detail`、`stage`）。

## 输出文件结构

### 文件命名（机器接口）

```text
<原图名>_<像素格式>_qoi_<be|le>_<宽>x<高>.bin
```

字节序**不存在于文件内部**，只体现在文件名的 `be|le` 段（或由工程约定提供）。

### 6 字节通用资源头

所有 `.bin` 都以 6 字节头开始，之后紧跟 QOI 数据流（数据流本身无任何头，也无结束码）：

```text
byte0   = 资源类型，恒 0x00（图片）
byte1   = 格式码：高 nibble 压缩算法，低 nibble 像素格式
byte2-3 = 宽，恒大端
byte4-5 = 高，恒大端
```

- 本工具算法 nibble：`0x3`（全表：`raw=0x0 rle=0x1 imprle=0x2 qoi=0x3 indexqoi=0x4 qoif=0x5 indexqoimask=0x6`）
- 像素格式 nibble：`RGB565=0x0 RGB888=0x1 RGB332=0x4 ARGB8888=0x5 ARGB6666=0x6 ARGB4444=0x7 ARGB8565=0x8 ARGB2222=0x9 RAGB5155=0xA`（`0x2/0x3/0xF` 保留不用）

## 像素来源与预处理（编码语义）

1. 输入图片统一解码为每像素 8bit 的 `R,G,B,A`；没有 Alpha 通道的输入（如 JPG）视为 `A=255`
2. **非 Alpha 目标格式**（`rgb888/rgb565/rgb332`）先把透明区域与背景色混合（整数运算，除法向下取整）：

   ```text
   out = (src * A + bg * (255 - A) + 127) / 255
   ```

3. 8bit 通道量化到 n 位：`Qn = (v8 * ((1 << n) - 1) + 127) / 255`
4. 例外：`RAGB5155` 的 1bit Alpha 用阈值 `A1 = (A8 >= 128) ? 1 : 0`
5. 带 Alpha 的目标格式不做背景混合，RGB 通道直接量化原始值

## 彩色格式打包规则（9 种）

像素顺序恒为**从左到右、从上到下**。大端布局如下；**小端 = 把单个像素的全部字节整体反转**；单字节格式（`rgb332/argb2222`）两种模式输出一致。

| 格式 | 字节数 | 大端布局（bit 高→低） | `0xFE` 后接 | `0xFF` 后接 |
| --- | --- | --- | --- | --- |
| `argb8888` | 4 | `A8, R8, G8, B8` | 3 字节 RGB（同端序） | 4 字节完整像素 |
| `argb6666` | 3 | `A[5:0]R[5:4]`，`R[3:0]G[5:2]`，`G[1:0]B[5:0]` | 不使用 | 3 字节完整像素 |
| `argb4444` | 2 | `A[3:0]R[3:0]`，`G[3:0]B[3:0]` | 不使用 | 2 字节完整像素 |
| `argb2222` | 1 | `A[1:0] R[1:0] G[1:0] B[1:0]` | 不使用 | 1 字节完整像素 |
| `argb8565` | 3 | `A8` + `(R5<<11)|(G6<<5)|B5` 大端 | 2 字节 RGB565（同端序） | 3 字节完整像素 |
| `rgb888` | 3 | `R8, G8, B8` | 3 字节 | （编码器不产出） |
| `rgb565` | 2 | `(R5<<11)|(G6<<5)|B5` 大端 | 2 字节 | （编码器不产出） |
| `rgb332` | 1 | `(R3<<5)|(G3<<2)|B2` | 1 字节 | （编码器不产出） |
| `ragb5155` | 2 | `(R5<<11)|(A1<<10)|(G5<<5)|B5` 大端 | 不使用 | 2 字节完整像素 |

Alpha 蒙版格式（`a8/a4/a2/a1`）由 `img2bin_raw`（全部四种）与 `img2bin_indexqoimask`（仅 `a8`）支持，本工具显式点名会报错（退出码 1）。

## QOI 数据流规则

所有比较、哈希与差分运算都在**量化后的目标格式通道值**上进行（例如 `rgb565` 用 R5/G6/B5，`argb4444` 用 A4/R4/G4/B4），不是 8 位 RGBA。

### 解码状态与初始值

- `prev`：前像素通道状态，初始 `r=0, g=0, b=0`，`a =` 该格式 Alpha 位宽的最大值（`argb8888/argb8565` 为 255、`argb6666` 为 63、`argb4444` 为 15、`argb2222` 为 3、`ragb5155` 为 1、非 Alpha 格式恒 255）
- `table[64]`：哈希字典，初始全部为"无效项"（未写入过的槽位不可命中）
- 哈希公式（`r/g/b/a` 为量化通道值；非 Alpha 格式 `a` 恒按 255 参与）：

  ```text
  hash = (r*3 + g*5 + b*7 + a*11) & 63
  ```

### op 一览（首字节区分）

| op | 名称 | 语义 |
| --- | --- | --- |
| `0x00..0x3F` | INDEX | `当前像素 = table[op]`；引用无效槽位视为损坏流 |
| `0x40..0x7F` | DIFF | `dr=((op>>4)&3)-2, dg=((op>>2)&3)-2, db=(op&3)-2`；当前 = 前像素分量 + 差值，Alpha 沿用前像素 |
| `0x80..0xBF` + 1 字节 | LUMA | `dg=(op&0x3F)-32`；第 2 字节 `b`：`dr=dg+((b>>4)&0xF)-8, db=dg+(b&0xF)-8`；Alpha 沿用前像素 |
| `0xC0..0xFD` | RUN | 把前像素重复输出 `(op&0x3F)+1` 次（1..62） |
| `0xFE` + 颜色字节 | 颜色原始块 | 按上表字节数读入 RGB 部分，Alpha 沿用前像素 |
| `0xFF` + 完整像素 | 完整原始块 | 按上表字节数读入完整像素（含 Alpha） |

- DIFF/LUMA 结果超出该格式通道位宽范围（如 `rgb565` 的 R 超出 `0..31`）视为损坏流
- 字典写入时机：解码执行 `DIFF/LUMA/0xFE/0xFF` 得到新像素后写入 `table[hash(新像素)]`；`INDEX` 与 `RUN` 不写入
- 每个 op 输出的像素同时更新 `prev`
- 数据流没有文件头和结束码：解码按 `宽 × 高` 像素数到数即停；提前耗尽 = 截断，产满后仍有剩余字节 = 多余数据

### 编码器 op 选择顺序（保证输出唯一，可对拍）

对每个像素依次尝试，命中即产出：

1. 与前像素完全相同 → 累计 RUN（累计到 62 或图像最后一个像素时写出）
2. 否则先写出未完的 RUN，再查字典：`table[hash]` 有效且与当前像素完全相同 → 写 INDEX
3. 否则把当前像素写入 `table[hash]`，然后按序尝试：Alpha 未变且可 DIFF → DIFF；Alpha 未变且可 LUMA → LUMA；Alpha 未变且该格式支持 `0xFE` → `0xFE`；其余 → `0xFF`

## 使用示例

```powershell
.\img2bin_qoi.exe --format argb8888
.\img2bin_qoi.exe --format rgb565 --bg-color FF0000
.\img2bin_qoi.exe --input .\photos --output .\out --formats all --manifest
```
